# SeQUeNCe fibre experiment

This folder implements the second half of the project requirement: **model BB84 key throughput versus fibre length using SeQUeNCe**.

The runner is based on SeQUeNCe's QKDNode/BB84 protocol stack and writes a CSV that the QuantumLab browser dashboard can import.

## Setup — Windows

Use Python 3.12+ and install the simulator:

```bat
python -m venv .venv
.venv\\Scripts\\activate
python -m pip install -r requirements.txt
```

If you already installed SeQUeNCe globally, you can run the script directly with that Python.

## Quick real SeQUeNCe validation (recommended first)

The full default sweep is intentionally much larger and can take a long time because SeQUeNCe is a discrete-event simulator. Start with the real, short validation run:

```bat
python sequence_distance_bb84.py --quick
```

This runs **real SeQUeNCe** at 1, 10, 50 and 100 km using a 0.0002-second simulation window per distance. It is for validating the installation, CSV generation and dashboard import.

Expected output files:

- `results/distance_bb84.csv`
- `results/distance_bb84_metadata.json`

## Full sweep

For the complete 12-point experiment:

```bat
python sequence_distance_bb84.py
```

The default uses 1–100 km and a 6-second simulation window per distance. This can be computationally expensive. Do **not** use the full run merely to test whether the project works.

You can also choose your own short sweep:

```bat
python sequence_distance_bb84.py --distances 1,10,20,40 --duration 0.0002
```

## Dashboard import

1. Start the web app with `npm run dev`.
2. Open **Fibre Analysis**.
3. Click **Import SeQUeNCe CSV**.
4. Select `sequence_experiment\\results\\distance_bb84.csv`.

The dashboard accepts the exact CSV column names generated by the Python runner (`Distance_km`, `Distance_m`, `Throughput_bits_per_second`, `Error_rate`, `Latency_ns`) and labels the result **SEQUENCE DATA**.

## Scientific scope

The experiment reports the SeQUeNCe BB84 protocol's throughput/error-rate behaviour. It does not label throughput as a secure final key rate. A final secure key requires authenticated sifting, parameter estimation, error correction and privacy amplification, which are outside this project's implemented scope.
